# HOWTO: кто вызывает эндпоинт бэкенда — `http-calls`

[English version](http-calls.md) · часть [HOWTO](howto.ru.md)

`ast-index http-calls` выдаёт вызовы бэкенда из фронтенда: модулей JS/TS/Vue и встроенных
`<script>` PHP-шаблонов. Для каждого вызова — метод, адрес, отправляемые ключи и ключи, которые
код читает из ответа. Отвечает на вопросы «кто вызывает этот эндпоинт», «что страница туда
шлёт», «какие вызовы меняют данные».

```bash
ast-index http-calls --path src/modules/orders         # один каталог, текстом
ast-index http-calls --format json > calls.json        # всё, для скрипта
```

Запускать из корня проекта: импорты разрешаются по всему индексу, `--path` только отбирает, что
печатать.

## Найти вызывающих одного эндпоинта

```bash
ast-index http-calls --format json \
  | jq '.calls[] | select(.url != null and (.url | startswith("/api/v1/orders/")))'
```

Вызов показывается там, где запрос делается **с точки зрения вызывающего**: вызов через обёртку
или клиент-объект стоит на строке, которая вызывает обёртку, с адресом, который эта строка
передаёт. Внутри самой обёртки адрес — всего лишь параметр, там вызова нет.

## Что распознаётся

| Вид | Пример | `client` / `via` |
|---|---|---|
| `fetch` | `fetch('/api/x', { method: 'POST', body: JSON.stringify(data) })` | `fetch` |
| axios и его экземпляры | `axios.get(url)`, `api.post(url, data)` при `const api = axios.create()` | `axios`, `axios-instance` / `api.post` |
| экземпляр, прошедший через функцию | `const api = withAuth(axios.create())` — подключены интерцепторы | `axios-instance` |
| jQuery, Bitrix | `$.ajax`, `$.post`, `$.get`, `BX.ajax`, `BX.ajax.runComponentAction`, `BX.ajax.runAction` | `jquery`, `bx.ajax`, … |
| функция-обёртка | `function post(url, data) { return api.post(url, data) }`, в том числе импортированная | `wrapper` / `post` |
| клиент-объект фабрики | `createClient()` возвращает `{ get(url, config) {…}, post(url, data, config) {…}, request }` | `wrapper` / `createClient.get` |
| метод того же объекта | `this.request({ url, method: 'DELETE' })`, в том числе в опциях компонента (`mounted()` вызывает метод из `methods`) | `wrapper` / `this.request` |

Обёртка или метод клиента распознаётся по тому, **что он пересылает**, а не по имени. Метод
`get(url, config)`, который вызывает `request({ ...config, method: 'get', url })`, а тот —
`instance.request(config)`, берёт HTTP-метод из литерала `'get'`, адрес — из аргумента 0, query —
из `params` аргумента 1. `post(url, data, config)` отправляет аргумент 1 телом.
`request(config)` читает `method`, `url`, `data`, `params` из объекта-литерала, который передаёт
вызывающий.

### Откуда берётся клиент-объект

Получатель `http.get(…)` прослеживается до вызова фабрики, которая его создала:

```js
const http = createClient()                                      // константа модуля или локальная
export function createApi(http = createClient()) { … }           // значение параметра по умолчанию
export function createApi({ client = createClient() } = {}) { … } // деструктурированный параметр
const client = injected || createClient()                        // `||`, `??`, `?:`, `as T`, `!`
import { http } from '@/shared/http'                             // импорт: `export … from` и
                                                                 // `export { x }` импорта прослеживаются
var Api = (function () { return { get(url) {…} } })()            // объект-модуль IIFE
```

Экспорты, собранные из импортированных, прослеживаются по цепочке: фабрика → индекс, который её
реэкспортирует → `export const http = createClient()` в другом модуле → обёртка над этим
клиентом → вызывающий обёртки.

Клиент, пришедший параметром **без** значения по умолчанию, ничего не говорит о том, что он
такое: вызов не выдумывается, адрес остаётся в «addresses outside recognised calls».

### Как сворачивается адрес

| В коде | В выводе |
|---|---|
| `'/api/items/'` | `/api/items/` |
| `` `/api/items/${id}/` `` | `/api/items/{id}/` — остальное как `{выражение}`, совпадает с `{id}` маршрута |
| `ITEMS_ENDPOINT` — константа модуля, в том числе импортированная | её значение |
| `ENDPOINTS.list`, в том числе через `Object.freeze({…})` | значение этого ключа |
| `ENDPOINTS[operation]` — ключ неизвестен | **по вызову на каждое значение** объекта |
| `itemUrl(id)` при `const itemUrl = (id) => \`/api/items/${id}/\`` | адрес помощника |
| `this.apiUrl('/orders/')` — метод того же объекта | адрес метода |
| `endpoint` — параметр с непустым значением по умолчанию | это значение (пустое остаётся `{endpoint}`); так же для обёртки, вызванной без аргумента-адреса |

Если не свернулось ничего, `url` равен `null`, а `url_expr` содержит выражение как написано.

## Отправляемые и читаемые ключи

- `params` — ключи отправляемого объекта-литерала: тело `post`/`put`/`patch`, `params` конфига,
  `JSON.stringify(obj)`, `FormData.append('key', …)`.
- `reads` — пути, которые код читает из ответа: `.then(cb)` (колбэк на месте или локальная
  функция), `await` в переменную или деструктуризацию, success-колбэки.
- `response_keys` — то же без конверта клиента: `data` axios отбрасывается, если обёртка уже не
  возвращает `response.data` сама.

## Проверить, распознаётся ли шаблон

1. `ast-index http-calls --path <модуль API>` — вызов должен быть в списке с методом.
2. Если его адрес в **«addresses outside recognised calls»** (`literals` в JSON), вызов вокруг
   него не распознан. Частые причины:
   - клиент пришёл параметром без значения по умолчанию или из класса (`this.http.get` в классе,
     созданном через `new`) — не прослеживается;
   - обёртка сама строит адрес из параметра (`` get(path) { return api.get(`/api/${path}`) } ``) —
     вызов показывается внутри обёртки, параметр на месте дыры;
   - фабрика возвращает объект не через `return { … }` или `return createOther()` (экземпляр
     класса, `Object.assign`).
3. Строки, из которых свёрнут адрес (константы, значения карт, помощники), больше не числятся вне
   вызовов; то, что там осталось, стоит посмотреть.

## Что не распознаётся

- Классы как клиенты (`new ApiClient()`, `this.http`, заданный в конструкторе).
- Объекты, которые никто не может назвать: возвращённые из CommonJS `module.exports = function`,
  из колбэка AMD `define`, из метода класса. Вызовы их методов показываются внутри них, с
  параметром вместо адреса.
- Клиенты, переданные дальше после создания (положены в store, provide/inject) — кроме значения
  параметра по умолчанию.
- Динамические имена методов (`http[method](url)`), адреса, собранные в цикле.
- Обёртка, чей адрес не берётся прямо из её параметров (префикс + параметр): вызов показывается
  внутри обёртки.
- Обёртка, делающая несколько вызовов с переданным ей адресом: её вызывающие получают первый.

## JSON

```json
{
  "path": "src/modules/orders/api.js",
  "line": 12,
  "client": "wrapper",
  "via": "createClient.post",
  "method": "POST",
  "url": "/api/orders/",
  "params": ["offerId", "quantity"],
  "reads": ["data.order"],
  "response_keys": ["data.order"]
}
```

`component`, `action`, `mode` — у действий компонентов Bitrix; `url_expr` — когда адрес не
свернулся. `literals` — адреса вне распознанных вызовов; `globals` — данные `window.X`, которые
шаблон передаёт скриптам.
